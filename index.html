Case study

Public repo / live showcase

MovieBot reduces the manual work behind Twitch movie nights.

MovieBot is a Python Twitch bot that turns chat commands into a watch-party queue. It tracks votes, handles stream-room commands, refreshes tokens, and hands the winning local media file to OBS.

Open Movie Night View source
Python TwitchIO OBS WebSocket OAuth refresh Static showcase
Problem

Manual stream chores

Movie voting, queue checks, result tallying, and media-source swaps created too much host overhead during a live watch party.

Constraints

Local files, public chat

The bot needs to respect the local movie folder, survive long sessions, validate chat commands, and recover cleanly from Twitch or OBS connection trouble.

Role

Built end to end

I built the vote commands, result handling, token refresh, OBS handoff, static movie pages, and searchable public-domain library.

Next

Better operator view

The next useful pass is a small control/status panel for queue state, current votes, OBS connection health, and upcoming media.

Project Spotlight

Public demo / case study

TraverseOps turns field work into a shared map.

I built TraverseOps as a focused municipal operations app for crews who need to find assets, record what happened on site, and turn problems into trackable work. The public app is a demo workspace with sample data, not an active municipal deployment.

Open TraverseOps demo Ask about the build
Demo workspace MapLibre Supabase Offline-aware sync Capacitor shell
Problem

Records scattered across tools

Field crews need to find assets, record site details, and create work orders without reconciling notes across disconnected systems later.

Constraints

Field-friendly and demo-safe

The public version uses sample data, keeps the app browser-first, and structures the UI around map-first asset lookup and offline-aware workflows.

Role

Designed the product shape

I built the asset map flows, registry/detail panels, inspection and work-order screens, and the sync-oriented front-end structure.

Next

Deeper case-study page

A fuller write-up should show the inspection flow, work-order lifecycle, sync states, and decisions behind the map/detail layout.

Current rule

Make the useful version first. Make it pretty after it survives real use.
