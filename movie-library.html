MovieBot system surface

A public voting catalog for the Twitch movie bot.

MovieBot needs a viewer-facing catalog so people can find eligible public-domain titles before sending Twitch chat commands. I built this static companion page with title/year/runtime/rating filters, copy-to-clipboard vote commands, lazy-loaded poster cards, accessible labels, and a complete no-JavaScript fallback so the movie queue remains readable without the dynamic UI.

Technical problem

Viewers need to find eligible public-domain titles and copy valid !vote commands without adding friction to the live chat flow.

Constraints

The page is static, depends on external poster images and IMDb links, and still needs to remain readable when JavaScript or posters fail.

Approach

I rendered a searchable HTML/CSS/JavaScript catalog with filterable metadata, generated vote commands, Clipboard API fallback logic, lazy posters, and noscript content.

Tradeoff

Keeping the catalog static makes GitHub Pages deployment easy, but movie data and fallback markup must be kept in sync when titles change.

Next improvement

The next pass would generate the dynamic cards and fallback list from one data source, add poster health checks, and surface stronger catalog QA.

What I built

  • Built a searchable catalog that filters public-domain MovieBot queue data by title, year, runtime, and rating.
  • Implemented copyable !vote commands with button labels and feedback so viewers can send accurate Twitch votes.
  • Added lazy-loaded poster cards, accessible metadata, and normalized external poster URLs for the static movie dataset.
  • Kept a complete ordered movie list in noscript markup so the catalog still works without JavaScript.

External pieces include IMDb links, externally hosted poster images, and public-domain movie metadata; the catalog UI and filtering/copy behavior are custom static-site code.

Voting workflow

Each rendered movie card includes a title-specific copy button so a viewer can send !vote Movie Title to Twitch chat without manually retyping long or ambiguous titles.

Public-domain catalog

The list is built around public-domain movie-night data: title, year, runtime, IMDb rating, IMDb link, and poster URL for each queue item.

Static fallback

If JavaScript is disabled, a full ordered list remains available in the page markup so the catalog still works as a readable static queue.

Poster performance

Poster images are rendered with fixed dimensions, async decoding, and lazy loading where appropriate so the large catalog does not block the first view.

Technical notes

Frontend details behind the catalog.

Search and filtering

Vanilla JavaScript filters the in-page movie data by title, year, runtime, or rating and updates the visible result count through an aria-live toolbar.

Vote command copying

Each card stores its generated !vote command in a data attribute. The copy flow uses the Clipboard API with a textarea fallback and temporary copied/failed button states.

No-JS fallback

The noscript block includes the full static list, preserving movie discovery even when filtering, copy buttons, and dynamic poster cards are unavailable.

Image loading strategy

Poster URLs are normalized for a larger card image, constrained to the expected poster host, and rendered with loading="lazy", dimensions, and async decoding.

Accessibility labels

The search input has a visible label, copy buttons include movie-specific accessible names, IMDb links describe their destination, and poster images use title-specific alt text.
